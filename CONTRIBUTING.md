# Contributing

This repository is a learning record and portfolio. Keep changes clear, reproducible, and tied to the roadmap or a documented project.

## Before adding work

1. Match the original roadmap module number, name, topic wording, and order.
2. Put learning notes, topic-focused work, and related projects in that module’s directory. Keep projects alongside the module they support.
3. Check for existing work before adding a second implementation of the same idea.

## Content expectations

- Explain assumptions, key ideas, and sources in notes.
- Include runnable examples for implementations, with clear inputs and expected behavior.
- Keep notebooks focused; move reusable logic into source files when it grows beyond exploration.
- Do not commit secrets, private datasets, large generated artifacts, or environment-specific files.
- Give each major project its own README, source code, tests, and dependency file or environment specification where appropriate.

## Changes and review

- Use descriptive commit messages and keep each change focused.
- Update roadmap checkboxes only when the corresponding topic work is complete.
- Run the checks relevant to the changed code and record how to reproduce them.
- Ensure documentation includes setup and usage instructions for runnable work.
